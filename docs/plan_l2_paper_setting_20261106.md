## 2. 为什么 f₁ 会依赖编辑，而不是依赖 e 本身

`resample` 只在熵 ≥ `min_entropy` 的位置编辑（`l0/resample.py`）。设纯水印位置的枢轴分布是按熵混合的：高熵位置水印信号强（`Y` 偏向 1），低熵位置接近均匀。则：

1. 编辑集中在高熵位置，存活的 truth=1 位置里高熵位置比例下降；
2. 存活位置的 `f₁` 比纯水印的更接近均匀，尾部质量（`P(Y ≥ 0.99)`）更低；
3. 编辑率越高，被抽走的高熵位置越多，偏离越大；而编辑率越高，估计占比 `e'` 越小。所以 `f₁` 与 `e'` 同向相关。

关键是：**`f₁` 依赖的是"编辑选择性"，e 只是它的代理。** 同一个 e，若来自 splice（水印位置整段未动），`f₁` 就是纯水印；若来自 R0（随机位置编辑，不看熵），按上述机制也应无偏离。`f₁(e')` 只在"熵选择性编辑"这一类上有依据，在别的场景用它会用错分布。本轮把这个当作**要检验的假设**，不当作已知事实（§3.3、§7）。

### 3.3 机制对照（训练侧，不读 test）

在 K1 数据上（`cal_pure`、`mix_r2`、`mix_r0`、`mix_splice`）做，结果决定 `fe` 的解读方式（§7），**不用于选参数**。用 `tmp/f1chk.py` 的思路，按编辑率分组：

1. truth=1 位置的 `P(Y≥0.99)`、`P(Y≥0.9)` 与纯水印之差，及按整篇文章自助的 95% 区间；
2. 纯水印位置的 `Y` 分布随熵分档的变化（`sources.jsonl` 记录了生成时概率，据此算熵；**训练侧的 `sources.jsonl` 必须保留**）；
3. 被编辑位置的熵分布，对比全部位置的熵分布；存活位置的平均熵，对比纯水印。

**事先写下的预测（写死）：**

- **M1**：`mix_r2` 的 truth=1 尾部质量低于纯水印，编辑率 ≥ 0.2 时差 ≥ 0.03 且区间不含 0；差随编辑率单调扩大。
- **M2**：`mix_r0` 与 `mix_splice` 的 truth=1 尾部质量与纯水印之差，区间含 0 且 |差| < 0.03。
- 若 M1 不成立：`fe` 仍照常跑，但解读为"机制不存在时的对照"，不当作新方案。
- 若 M1 成立而 M2 的 `mix_r0` 也出现偏离：说明偏离不来自熵选择，改为单独解释，`fe` 的假设需重写（另起版本）。

### 3.4 论文 Setting 的构造

1.pdf 的 Setting（`papers/text/segment_existing.txt:531-580`），m=500：

| Setting | 论文构造 | 水印段（最终坐标，0 起） | 真值切换点（0 起） |
|---|---|---|---|
| 1 | 500 个水印 token | [0, 500) | 无 |
| 2 | 250 个水印 + 250 个非水印（追加） | [0, 250) | 250 |
| 3 | 500 个水印，替换 201–300 为非水印 | [0, 200)、[300, 500) | 200、300 |
| 4 | 400 个水印，替换 101–200 为非水印，再在 300 处插入 100 个非水印 | [0, 100)、[200, 300)、[400, 500) | 100、200、300、400 |

论文没有写非水印文本从哪里来。**本文的实现选择**：对每个 prompt 另做一次同模型、同 prompt、不加水印的 500 token 生成 `U`，水印文本为 `W`；`U` 与 `W` 的采样种子独立。

- Setting 2：`W[0:250] + U[250:500]`；
- Setting 3：`W[0:200] + U[200:300] + W[300:500]`；
- Setting 4：先取 400 个水印 token，`W[0:100] + U[100:200] + W[200:300] + U[300:400] + W[300:400]`，共 500。

这个选择必须写进报告。其余照论文：长度 500、每个 Setting 100 篇、OPT-1.3b。

**真值。** 沿用 `truth = S − B`：`S` 是水印来源位置，`B = E ∪ [t+1, t+4]`，`E` 取所有非水印拼入的位置。这样每个"非水印 → 水印"接缝之后的 4 个位置记为非水印（它们是在原上下文下生成的，换了上下文后枢轴变成均匀）。"水印 → 非水印"接缝之后是非水印文本，枢轴本来就均匀，不受影响。**论文式 Rand index 用无缺口的真值切换点**（上表），IoU 用 `S − B`。切换点要从 token 坐标换到枢轴坐标（前 4 个位置没有枢轴，减 4）。

**与论文的差别要写明：** 逐位置检测量不是差别：论文 EMS 的 `log ξ_{i,ỹ_i} + 1`（式 (2)）与我们的 `log Y_t + 1` 是同一个量（`Y_t` 就是被选 token 对应的均匀随机数，见旧 plan §5.3）。差别在三处：论文的钥匙是按位置取的序列，本项目是上下文哈希，位置天然对齐，不需要钥匙对齐搜索；论文的随机化 p 值用"换新钥匙"，我们用 iid `U(0,1)` 代替；论文只输出切换点，我们补了一步段检验才得到逐位置标签。所以这轮只能说"沿用论文的数据构造与评价指标，检测量与算法按其适配"，不能说"复现论文方法"。

### 3.5 密度延拓：等长交替段

**动机。** SeedBS 的理论条件与实现都假定切换点之间相隔足够远：论文的运行设定里最短区间 50（`2.5B`），其定理的难度由切换点间距与变化幅度决定，附录 B.5 里切换点 4、8 个全部找回，12 个只找回 9 个（`segment_existing.txt:1893-1902`）。切换点越少越适合它，这是论文自己的说法；Setting 2–4 只有 1、2、4 个切换点（间距 100 以上）。而 `resample_0.1` 的切换密度高得多。所以需要一条连续的密度阶梯，看两类方法各在哪里掉下去。

**构造。** 水印段与非水印段等长 `L` 交替，从水印段开始：`W[0:L] + U[L:2L] + W[2L:3L] + …`，最后一段截断到 500。仍用替换（不插入），真值沿用 `S − B`，论文式 Rand index 用无缺口的真值切换点。切换点数 `K = ⌈500/L⌉ − 1`。

**段长阶梯：**

| 档 | `L` | `K` | 与 `resample_0.1` 的关系 |
|---|---:|---:|---|
| A1 | 50 | 9 | 间距 = `seedbs` 最短区间 |
| A2 | 25 | 19 | 间距 < 最短区间，已在 `seedbs` 的分辨率之下 |
| A3 | 12 | 40 | |
| A4 | `L_top` | `K_top` | **与 `resample_0.1` 的切换密度相当** |

加上论文的 Setting 2、3、4（`K = 1, 2, 4`）与 B.5 的量级，一共覆盖 `K ∈ {1, 2, 4, 9, 19, 40, K_top}`。

**`L_top` 的定法（写死，在生成评价侧数据之前执行）。** 在训练侧 `mix_r2` 编辑率 0.1 的 40 篇上数真值切换点（枢轴坐标、`S − B` 口径）的平均数 `K̄`，令 `L_top = round(500/(K̄+1))`，`K_top = ⌈500/L_top⌉ − 1`。不用测试侧的数据来定。

**事先的粗估，只供参考。** 在 500 个位置上随机均匀选 50 个编辑位置、破坏窗口 5 个位置（含编辑位置本身与其后 4 个）的模拟里，平均有约 59 个切换点（约每 8.5 个位置一个），存活位置占比约 0.59，存活游程中位数 7。这对应 `L_top ≈ 8`。真实的熵选择性编辑会让编辑更集中，切换点可能更少，所以以实测的 `K̄` 为准。

**两点区别要如实写。** 等长交替段是规则的，`resample` 的存活游程长短不一，所以密度相当并不等于难度相当。另外 `L=8` 时每个水印段扣掉接缝后的 4 个位置，只剩 4 个真值水印位置，这与 `resample_0.1` 的存活游程（中位 7）量级一致，是有意为之。

**训练与泛化。** `mix_alt`（四档各 30 篇）与 `mix_splice` 一样进入 `A` 的训练，所以 `test_alt` 对 `A` 是域内的；报告里同样标注，不据此声称对未见结构泛化。`A` 是全局两参数，同时拟合 `K=1` 到 `K_top` 的不同粘性，是折中值，各档的结果分别报告。

## 4. 方法

### 4.1 估计顺序（对每个臂各做一次）

严格按序，前一步冻结后才做后一步；`test_*`、`null_test` 到最后一步前不可读。

1. **阶段 1 的 `f₁`**：纯水印 hist200（`m100` 用 100 篇，`m400`、`fe` 用 400 篇），临时 `cap=25`。
2. **`e'`**：对每篇文章（训练、dev、null、test）用阶段 1 的 `f₁` 与 `cap` 算 `ε̂_opt`（旧 plan §5.1），记作 `e'`。PD 的 `π_d = (1−e', e')`。
3. **阶段 2 的 `f₁`**：`m100`、`m400` 沿用阶段 1；`fe` 按 §4.2 构造 `f₁(·; e)`。
4. **`A`、`π`**：在 `mix_r2 ∪ mix_splice`（360 篇，不含 `mix_r0`）上做池化 EM（旧 plan §5.2）。`fe` 的每篇用自己的 `f₁(·; e'_d)`；PD 的 `π_d` 固定为 `(1−e'_d, e'_d)`。
5. **选择（`dev`）**：`cap ∈ {5, 10, 25, 50, 100, 不截断}`；`fe` 另选 `h ∈ {0.05, 0.1, 0.2, 0.4, ∞}`，与 `cap` 联合选。选法同旧 plan §3.3：每个 `h` 先用临时 `cap` 估 `A`，再选 `cap`，最后重估一次 `A`。`dev` 上的选择准则是 3 类的等权平均 IoU：论文类（Setting 2、3、4 合并取平均）、交替类（四档平均）、R2 类（两个编辑率平均），要求 `τ<1` 且可检出位置数 > 0；IoU 相同取较少截断者、较大的 `h`。
6. **`τ`**：`null_cal` 上按方法校准，`α=0.05`，沿用旧实现；`seedbs` 的 `c` 同理。
7. **冻结**：把 `f₁`（含 `fe` 的网格密度与 `h`）、`cap`、`A`、`π`、`τ`、`seedbs` 的 `(B, ζ, c)` 写进 `frozen.json`。
8. **一次 test**：全部方法在 `test_paper`、`test_r2`、`test_r0` 上跑一次，`null_test` 上跑 any-FP。

### 4.2 `f₁(·; e')` 的构造（`fe`）

**训练数据**：`cal_pure` 与 `mix_r2` 中 truth=1 的位置。每个位置带一个权重依据：它所在文章的 `e'`（不是真值 `ε`；训练与推理都用估计值，两边口径一致）。纯水印文章的 `e'` 约为 0.999。

**核加权直方图**：对目标占比 `e`，位置 `i` 的权重 `w_i(e) = K((e'_{d(i)} − e)/h)`，`K` 取高斯核，截断在 3h。再把权重归一化，使总权重等于有效样本量 `n_eff(e) = (Σw)²/Σw²`，对 200 箱加权计数，各箱加 0.5 伪计数，得 `f̂₁(·; e)`。伪计数与无加权时的口径一致。

**连续延拓**：在网格 `e ∈ {0.05, 0.10, …, 1.00}` 上各拟合一份，推理时对 `e'` 做**密度的线性插值**（相邻两份密度的凸组合，保持非负、归一）。`e'` 小于 0.05 的取 0.05。`h=∞` 时所有位置权重相同，退化为 `m400`，所以 `h` 由 `dev` 选，选到 `∞` 就报告"`fe` 与 `m400` 相同"。

**`cap`**：在插值后的密度比上截断，与其他方法同规则。

**必须报告**：各网格点的 `n_eff(e)`；`n_eff(e) < 300` 的网格点标注，它们的密度估计不稳，不做局部加宽。

**要点：**

- `e'` 由阶段 1 的纯水印 `f₁` 得到，不迭代。`f₁(e')` 的估计误差不回传到 `e'`；若要迭代，须另起版本。
- `fe` 是基于 R2（熵选择性编辑）训练的，其适用域就是这一类编辑。它在 splice、R0 上用的是"错误"的 `f₁`，属域外使用，预期无收益甚至变差（§7），这是要如实报出的代价。
- 备选形式：对 `f_pure` 做指数倾斜 `f₁(y;e) ∝ f_pure(y)·exp(β(e)ᵀφ(y))`，参数少，对稀疏数据友好。本轮不用，只在核加权方案因 `n_eff` 不足而失效时作为下一版的候选。

### 4.3 `seedbs`

按旧 plan §5.3 的适配实现，改动如下：

- **论文式运行（`seedbs_paper`）**：`B=20`、`B′=20`、`a=1/√2`、最短区间 50（`=2.5B`）、`T=999`、`T′=1999`；`ζ ∈ {0.05, 0.01, 0.005, 0.001}` 四档**全报**，每档在 `null_cal` 上各自校准 `c`，报 Rand index 与 IoU。`a` 论文印作 `√2`，与它自己要求的 `a ∈ [1/2, 1)` 矛盾，仍取 `1/√2`，沿用旧 plan 的判断。
- **dev 选择版（`seedbs`）**：`B ∈ {6, 10, 14, 20}`、`ζ` 同上共 16 组，在 `dev` 上选，规则同旧 plan。主表里的 `seedbs` 取这一版。
- 按篇固定随机种子，写进 `frozen.json`。长度 500 的计算量显著高于长度 128：每个区间的 KS 扫描是 `O(l²)`，区间数也更多。`T′` 不降到 1000 以下，否则 `ζ=0.001` 形同虚设；预算不足时减少 `null_cal` 的 `B` 档数，不减 `T′`。

## 5. 评价与判据（预注册）

### 5.1 终点

- **主终点分三块，各自报告，不合并成一个数**：
  - 论文块：`test_paper` 的 Setting 2、3、4 的平均 IoU 与**论文式 Rand index**（对无缺口的真值切换点）；
  - 密度块：`test_alt` 四档各自的 IoU 与 Rand index，以及检出切换点数对真值切换点数之比，画成随 `K` 变化的曲线（与论文块的 `K=1,2,4` 接在同一条横轴上）；
  - R2 块：`test_r2` 两个编辑率的平均 IoU；
  - R0 块：`test_r0` 两个编辑率的平均 IoU。
- **次终点**：Setting 1 的 recall（真值全为 1）；Setting 1 下检出的假切换点数（`seedbs` 报四档 ζ，HMM 方法报标签切换次数）；边界误差；`ε̂` 误差；any-FP（`null_test`，重校准口径，`p95 ≤ 2α` 且中位 ≤ α）；`A` 的估计与 bootstrap 区间；`a₀₀ = a₁₁` 的似然比检验；Rand index 另报对 `S − B` 切换点的版本。
- 所有 ΔIoU 用配对 bootstrap（2000 次，按文章），区间为 95%。

### 5.2 判据（只有以下几条设门槛，其余只描述）

| 编号 | 内容 | 性质 |
|---|---|---|
| C1 | 误报：各 HMM 方法在 `null_test` 上重校准后 `p95 ≤ 2α` 且中位 ≤ α | 门槛 |
| C2a | `fe − m400` 在 R2 块（PD、PE 各算）的 ΔIoU，区间下界 > 0 | 门槛：成立才声称 `f₁(e')` 在其适用域内有帮助 |
| C2b | `fe − m400` 在 R0 块与论文块的 ΔIoU | **预测为 ≤ 0**（域外使用的代价）；只报方向与区间，不设门槛 |
| C3 | `m400 − m100`（样本量）在各块的 ΔIoU | 只报方向与区间 |
| C4 | HMM 各臂与 `seedbs`（论文式与 dev 选择版）的 ΔIoU 与 Rand index 之差，按块、按 `K` 逐档报 | 只报，不设判据；不预先声称谁在哪个密度领先 |

**C2a 与 C2b 的联合解读（写死）：**

- C2a 成立且 R0、论文块 `fe − m400 ≤ 0`：支持"收益来自熵选择性编辑，不来自额外的光滑或样本量"，同时给出域外使用的代价。
- C2a 成立且 R0 上 `fe − m400 > 0`：收益不能归因于熵机制，报告里写"来源未明"，**不**声称机制被证实。
- C2a 不成立：`f₁(e')` 在本数据上没有帮助，不改主线。

不对 C2a、C2b 做多重比较校正，但标明：C2a 与 C1 是确认性检验，其余是描述。

### 5.3 cap 细化对比（只作敏感性，不重新选）

对 `m100`（PD、PE）在更细的网格 `{2, 3, 4, 5, 6, 8, 10, 12, 15, 20, 25, 35, 50, 100, 不截断}`（hist200 的密度上界约 62，`≥ 62` 与不截断相同）上逐点跑：每个 `cap` 重估 `A`、在 `null_cal` 上重校准 `τ`。分组：

- 按场景：论文 Setting 1–4、交替四档、`resample_0.1/0.3`（R2）、R0 两档；
- 按 `e'` 三档：[0, 1/3)、[1/3, 2/3)、[2/3, 1]。

每组报：IoU、`τ`、any-FP、后验饱和比例、边界误差。结果只当敏感性曲线读：`m100` 的冻结 `cap` 是 `dev` 上选的，曲线上的 test 最优点**不**能用来改它。若曲线显示 `dev` 选的 `cap` 远离 test 最优点，如实写，不据此改主线（须另起版本）。

## 7. 注意与风险

| 风险 | 表现 | 预案 |
|---|---|---|
| 机制不存在 | M1 不成立，`mix_r2` 的 `f₁` 与纯水印无异 | `fe` 照跑但降级为对照；不改主线 |
| `fe` 在域外变差 | R0、splice 块 `fe − m400 < 0` | 这是预测中的代价，不是失败；报告里量化，并写"假设了熵选择性编辑" |
| `A` 对场景敏感 | R2 存活游程很短，splice 段长 100，同一个 `A` 难同时适配 | `A` 在两类混合上拟合；各块分别报；某一块明显吃亏，先归因于 `A`，不先归因于 `f₁` |
| 训练与测试同构 | `mix_splice` 与 `test_paper` 用同样的段结构，`A` 对它是域内 | 报告里写明；不据此声称 `A` 对未见结构泛化 |
| `e'` 的误差 | `ε̂_opt` 的误差均值约 0.065（长度 128 时），核带宽过小会放大噪声 | `h` 下限取 0.05 并由 `dev` 选；`fe` 以 `e'` 训练也以 `e'` 推理 |
| `e'` 与 `f₁` 的循环依赖 | `e'` 用纯水印 `f₁`，再用 `e'` 定 `f₁(e')` | 只做两阶段，不迭代 |
| 低 `e` 一端数据稀少 | `e'<0.1` 只有编辑率 0.5 的文章 | 报 `n_eff(e)`；`<300` 的格点标注；覆盖不足就补数据，不放宽阈值 |
| `f₀ ≢ 1` | 500 token 的重复上下文使枢轴不严格 iid | `null_cal` 上报 `sup|f̂₀ − 1|` 与逐箱偏差；与 iid 参考对照（旧 plan §6.4） |
| prompt 重叠 | 与旧角色共用行，熵结构共享 | §3.1 的行不相交约束；不满足必须在报告里写明 |
| 非水印文本来源 | 论文没写 | §3.4 的选择，写进报告；若换成"以 `W` 前缀为条件续写"，只影响文本，不影响枢轴分布 |
| 论文设置不等于论文方法 | 水印方案、检测量都不同 | 只称"沿用数据构造与评价指标"；`seedbs` 称"按 1.pdf 适配" |
| 计算量 | 500 token 的 `seedbs`；HF 回放生成 resample 的概率 | 训练侧先做，评价侧并行生成；`seedbs` 见 §4.3 |
| dev 只有 100 篇，选 `(h, cap)` 联合网格 | 选择噪声 | 报全部网格得分；不据 test 回头改 |
| 后验饱和与 `τ=1` | `cap` 太大时 | 沿用旧 plan §3.5 的处理与记录，不修补 |
| 解读被事后拉偏 | 看到 test 后改预测 | §3.3 的预测与 §5.2 的解读规则在生成评价侧数据之前定稿；任何变动另起版本 |

| `seedbs` 在密集切换点下的行为 | `L<50` 时 SeedBS 最短区间已大于段长；`null_cal` 校准的 `c` 也许使标签几乎全空 | 如实报；`seedbs_paper` 保持论文参数不动，dev 选择版允许选更小的 `B` |
| 交替段太规则 | 与 `resample` 的游程分布不同，密度相当不等于难度相当 | §3.5 写明；`test_r2` 仍是 `resample` 密度的直接证据 |

**样本量与分辨力。** 每块 100 篇，配对 ΔIoU 的区间半宽预计在 0.02 量级，对 0.01 以下的差异没有分辨力；报告里不对这类差异作方向性断言。

## 8. 总进度条（当前进度 / 总实验进度）

**要求：** 每一阶段运行时，终端和一个文件里都能看到整个实验的进度，形式是 `当前单位 / 总单位` 加一个百分比，外加当前阶段自己的子进度与剩余时间估计。

### 8.1 阶段表与单位（按本计划的篇数算出的总数）

单位是"一件可数的工作"，不同阶段的单位耗时差别很大，所以除了单位数，还要按权重算总百分比（§8.2）。程序启动时从配置重算这张表，下表是按当前配置的预期值，不一致以程序为准，并在日志里打出差异。

| 阶段 | 单位 | 预期总数 | 位置 |
|---|---|---:|---|
| G1 训练侧生成 | 一次生成请求（`W` 或 `U` 各算一次） | 1850 | 服务器 |
| B1 训练侧构建 | 一篇文章的回放与枢轴提取 | 1510 | 服务器 |
| D1 机制对照 | 整个检验 | 1 | 本地 |
| F1 `f₁` 拟合（阶段 1） | 一个臂 | 2 | 本地 |
| E1 EM（含重估） | 一次 EM 运行 | 28 | 本地 |
| S1 `dev` 选择 | 一个 `(臂, π, h, cap)` 候选的评价 | 84 | 本地 |
| S2 `seedbs` 选择 | 一组 `(B, ζ)`，加 `seedbs_paper` 的 4 档 | 20 | 本地 |
| T1 `τ` / `c` 校准 | 一个方法在 `null_cal` 上的一次校准 | 11 | 本地 |
| G2 评价侧生成 | 一次生成请求 | 700 | 服务器 |
| B2 评价侧构建 | 一篇文章 | 1600 | 服务器 |

| REP 报告 | 整个报告 | 1 | 本地 |

### 8.2 显示与权重

- **单位进度：** 每个阶段在每完成一个单位时计数，总进度显示成 `已完成单位 / 总单位`，并分阶段显示（如 `R1  7340/17600`）。
- **加权百分比：** 总百分比 = `Σ(阶段已完成单位 × 阶段单位权重) / Σ(阶段总单位 × 阶段单位权重)`。权重是每个单位的秒数，从一次小规模冒烟运行里测出，写进 `progress_weights.json`；没有测量值时按相等权重，并在进度条上标注"权重未校准"，因为这时 `R1` 的 17600 个单位会让前几个阶段看起来几乎不占进度。
- **剩余时间：** 用当前阶段最近 50 个单位的平均耗时乘以剩余单位数，加上后续阶段按权重折算的估计；只作参考，写成区间。
- **断点续跑：** 已有缓存的单位启动时就记为已完成，不重复计时，也不计入耗时估计。
- **输出位置：** 终端（`stderr`）刷新一行；每次更新同时原子写入输出目录下的 `progress.json`（含各阶段的完成数、总数、权重、已用时间、当前阶段、预计剩余），这样断开终端后也能用 `watch -n 5 cat <输出目录>/progress.json` 查看。
- **与现有接口的关系：** `progress.py` 里的 `progress(stage, current, total, detail)` 保持不变，仍供 notebook 子进程读取；总进度作为另一类事件输出，不改变旧事件的格式。
- **服务器上生成阶段：** 以完成的请求数计数；若 vLLM 批量返回，按批内请求数一次性推进。

### 8.3 验收

- 冒烟配置下，全部阶段的单位总数与手算一致；
- 强制中断后重新启动，已完成单位不重复计数，总百分比不倒退；
- 某阶段全部命中缓存时，进度条能直接跳到该阶段末尾，不出现除零或剩余时间为负；
- 报告末尾写出各阶段实际单位数、实际用时，作为下一轮权重的初值。
